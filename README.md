# ระบบบริหารงานแนะแนวสำหรับองค์กร

ต่อยอดจาก React + TypeScript + Vite + Firebase เดิม สำหรับองค์กรเดียวที่บุคลากรใช้ข้อมูลโรงเรียนร่วมกัน

## เริ่มต้น

```powershell
npm ci
Copy-Item .env.example .env.local
# กรอก Firebase project ขององค์กรใน .env.local
npm run dev
```

เปิด http://localhost:3000 จากนั้นเข้าสู่ระบบด้วยบัญชีจริงที่ผู้ดูแลจัดเตรียมไว้
ตัวแปรว่างจะใช้ค่าโครงการเดิมจาก firebase-applet-config.json ต้องกำหนดค่าทั้งชุดเมื่อเปลี่ยนโครงการ
ห้ามใส่ service account หรือรหัสลับของเซิร์ฟเวอร์ในตัวแปร VITE_* เพราะถูกส่งไปยัง browser

## เตรียมบัญชีและฐานข้อมูล

1. เปิด Email/Password ใน Firebase Authentication และสร้างบัญชีผู้ดูแลผ่าน Firebase Console
2. คัดลอก UID สร้างเอกสาร `users/{UID}` ใน Firestore database ที่แอปใช้งาน โดยผู้ดูแลโครงการ:

```json
{
  "id": "UID_FROM_AUTHENTICATION",
  "email": "admin@example.org",
  "displayName": "ผู้ดูแลระบบ",
  "role": "ADMIN",
  "active": true
}
```

3. ตั้ง `VITE_FIREBASE_DATABASE_ID` ให้ตรงฐานข้อมูลจริง (`(default)` หรือชื่อฐานข้อมูล) และแก้ `firestore[].database` ใน firebase.json ให้ตรงกัน ค่าในไฟล์ปัจจุบันอ้างฐานข้อมูลชื่อเดิมของโปรเจกต์
4. ตรวจและเผยแพร่ firestore.rules ไปยังฐานข้อมูลนั้นผ่าน Firebase Console หรือ Firebase CLI โดยระบุ project อย่างชัดเจน โค้ดในเครื่องยังไม่เปลี่ยนกฎบนระบบจริง
5. สร้างบัญชีบุคลากรใน Authentication ก่อน แล้วใช้หน้าตั้งค่าเพิ่มโปรไฟล์ด้วย UID เดียวกัน การเพิ่มโปรไฟล์ไม่ได้สร้างบัญชี Authentication หรือส่งคำเชิญ
6. บัญชีเดิมที่ใช้ document ID แบบสุ่มต้องย้ายเป็น UID ของบัญชีจริงก่อน จัดการย้ายโดยผู้ดูแลโครงการและสำรองข้อมูลก่อน

| บทบาท | อ่านข้อมูลร่วม | บันทึกงาน | ลบงาน | ผู้ใช้/ตั้งค่า/ประวัติ |
| --- | --- | --- | --- | --- |
| ADMIN | ได้ | ได้ | ได้ | จัดการได้ |
| STAFF | ได้ | ได้ | ไม่ได้ | แก้ชื่อและโทรศัพท์ตนเอง |
| MANAGER | ได้ | ไม่ได้ | ไม่ได้ | แก้ชื่อและโทรศัพท์ตนเอง |
| VIEWER | ได้ | ไม่ได้ | ไม่ได้ | แก้ชื่อและโทรศัพท์ตนเอง |

สมาชิกที่ active ทุกบทบาทอ่านรายชื่อบุคลากรได้เพื่อเลือกผู้รับผิดชอบ สิทธิ์ยังไม่แยกอ่านตามทีม
ผู้ดูแลไม่สามารถลบ ปิดบัญชี หรือลดสิทธิ์ของตัวเองผ่านแอป

## สิ่งที่ปรับแล้ว

- ยืนยันตัวตนจริง ตัด anonymous/preset login, รหัสผ่านตายตัว, การสร้างบัญชีอัตโนมัติ และการเชื่อสิทธิ์จาก localStorage
- ติดตามโปรไฟล์ปัจจุบันแบบ realtime และปฏิเสธโปรไฟล์ที่ไม่มีสิทธิ์/ถูกระงับ
- Firestore rules ตรวจสมาชิกและบทบาท ป้องกันการยกระดับสิทธิ์ด้วยการแก้โปรไฟล์ตนเอง
- ปิดการใส่ข้อมูลตัวอย่างอัตโนมัติเมื่อเปิดแอป
- แก้การโหลด fieldTrips ให้เรียงฟิลด์ date และแสดงข้อผิดพลาดของข้อมูลที่โหลดไม่สำเร็จ
- เพิ่มตารางประวัติการทำงาน 50 รายการล่าสุดสำหรับผู้ดูแล
- การอัปโหลดภาพล้มเหลวจะแจ้งข้อผิดพลาด ไม่คืน data URL แล้วอ้างว่าบันทึกสำเร็จ
- ปิดการจำลองส่งอีเมลที่เคยบันทึก SENT ทั้งที่ไม่ได้ส่งจริง

## ตรวจสอบ

```powershell
npm run lint
npm test
npm run build
```

ชุดทดสอบฐานข้อมูลต้องติดตั้ง Java และ Firebase CLI ตามข้อกำหนดของ Firebase Emulator:

```powershell
firebase emulators:exec --only firestore --project demo-utt-enterprise "npm run test:rules"
```

ชุด rules ครอบคลุม public/anonymous, บัญชีไม่มีสิทธิ์/ถูกระงับ, อ่านตามบทบาท, จำกัดการเขียน, การยกระดับสิทธิ์, ป้องกัน admin ล็อกตัวเอง และการปลอมผู้บันทึกประวัติ

## ก่อนเปิดใช้จริง

งานครั้งนี้ยังเป็นฐานสำหรับทดลองภายใน ไม่ใช่การรับรอง production readiness:

- rules ผ่าน Emulator บน GitHub Actions แล้ว ต้องทำ UAT ด้วยบัญชีจริงทุกบทบาทก่อน deploy กฎและแอป
- ตรวจ Firebase Storage rules แยกต่างหาก ยังไม่ได้แก้หรือ deploy กฎ Storage ในงานนี้ ตรวจการเข้าถึงรูปและ download token URLs ตามนโยบายองค์กร
- ประวัติยังบันทึกจาก client ไม่ใช่ audit ที่รับประกันครบทุกการเปลี่ยนแปลง ต้องย้ายไป server ก่อนใช้เป็นหลักฐานตรวจสอบ
- การป้องกันนัดหมายชนกันยังเป็นการตรวจแล้วค่อยเขียน จึงมี race เมื่อหลายคนจองพร้อมกัน
- ไม่มีบริการอีเมลจริง/SSO/MFA/ระบบสำรองและกู้คืนอัตโนมัติ
- ตรวจและแก้ dependency audit โดยเฉพาะ xlsx ก่อนรับไฟล์ที่ไม่เชื่อถือ
- bundle ยังมีขนาดใหญ่ ควรแบ่งโหลดรายหน้าและโหลด Excel เฉพาะตอนส่งออก
